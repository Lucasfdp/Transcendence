## Errors / issues seen inside implemented modules

These are the most relevant concrete problems I found in modules that otherwise look implemented.

### 1. Weekly/monthly leaderboard query is logically wrong

- File: `backend/src/modules/users/users.controller.ts:245-252`
- Problem: `queryPeriod()` says it filters wins by date, but the SQL counts `mp.outcome = 'win'` from `match_players` before enforcing that the joined `matches` row is inside the requested period.
- Effect: weekly/monthly leaderboard numbers can behave like all-time numbers.
- Why: `LEFT JOIN matches m ... AND m."createdAt" >= $1` is not enough if `SUM()` and `COUNT()` only read `mp`.

### 2. Temple Curling abandon logic still assumes 2 players

- File: `backend/src/modules/matchmaking/engines/shell-curl.engine.ts:83-85`
- Problem: `abandon()` returns `1` when player `0` leaves, otherwise `0`.
- Effect: if Temple Curling is run with 3+ players, the winner chosen on abandonment can be wrong.
- This is the main reason I did not count the `Multiplayer > 2 players` major module yet.

### 3. 42 OAuth button is always enabled even when backend credentials are placeholders

- Files:
  - `frontend/src/components/auth/OAuthButtons.tsx:58-66`
  - `backend/src/modules/auth/strategies/forty-two.strategy.ts:16-23`
- Problem: the frontend always exposes “Continue with 42”, while the backend strategy falls back to `"placeholder"` credentials when env vars are absent.
- Effect: users can trigger a broken OAuth flow instead of seeing the option disabled or hidden.
- This weakens the confidence of the OAuth module as “done”.
